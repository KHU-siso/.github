## 💡 왜 MORAM인가

AI 도구는 이렇게 발전했는데, 왜 여전히 "학점 따기 어렵다"는 말이 나올까요?

처음에는 **"AI에게 물어도 우리 수업과 상관없는 답만 온다"** 는 가설로 시작했습니다. 그런데 경희대학교 학생 100명에게 설문해 보니, 학생들은 이미 AI 도구를 많이 쓰고 있었고, 가장 큰 어려움은 따로 있었습니다. **의욕 유지, 계획 세우기, 시간 관리**였습니다.

> **몰라서 안 하는 게 아니다. 알아도 하기 힘든 거다.**

그래서 문제를 다시 정의했습니다. 자료가 없어서가 아니라, **시작하기 힘들어서** 공부를 놓친다는 것. 답을 주는 AI는 이미 많으니, MORAM은 **시작하게 만드는 AI**를 목표로 합니다.

> **MORAM**은 순우리말 '모람모람'(이따금씩 한데 몰아서)에서 따왔습니다. 작은 배움이 모여 커다란 성장으로.

## ✨ 핵심 기능

| | 기능 | 설명 |
|---|---|---|
| 📚 | **과목별 AI 튜터** | 내가 올린 강의자료 PDF와 노트에 근거해서 답하는 과목별 대화 |
| 📝 | **퀴즈 · 오답노트** | 자료로 문제를 만들고 채점, 틀린 문제는 오답노트에 쌓이고 복습을 안내 |
| ⏰ | **먼저 말을 거는 알림** | 과제 마감 24시간 전, 그리고 시간표의 빈 시간에 메일로 먼저 알려 줌 |
| ⛄ | **옹이 · 코인 · 상점** | 퀴즈를 풀면 코인, 할 일이 밀리면 슬퍼하는 캐릭터. 코인으로 나만의 옹이를 꾸밈 |
| 🗓️ | **학습 대시보드** | 학습 목표, 우선순위별 해야 할 일, 주간 시간표·휴강을 한 화면에 |

### ⛄ 캐릭터 옹이

눈사람을 닮았지만 정해진 형태가 없는 존재입니다. 가지가 떨어진 자리를 나이테로 감싸 단단해진 나무옹이처럼, 모람모람 쌓인 공부가 나만의 옹이가 됩니다.
옹이는 장식이 아니라 **학습 데이터가 기분과 코인으로 바뀌는 인터페이스**입니다. 순위 경쟁 대신 내 안의 성장에 보상합니다.

| 코인 받기 | |
|---|---|
| 가입 선물 | 20코인 (계정당 1회) |
| 퀴즈 정답률 75% 이상 | 3코인 |
| 퀴즈 정답률 50% 이상 | 1코인 |
| 정답률 50% 미만 | 복습 안내 |

퀴즈 세트당 보상은 한 번만 받을 수 있습니다.

### 🆚 범용 AI(NotebookLM · ChatGPT)와 다른 점

| MORAM | 범용 AI |
|---|---|
| 시간표·과제·시험을 알고 **먼저** 알려 줌 | 물어봐야 답함 |
| 강의자료 + 내 노트 + 오답 + 일정을 함께 근거로 씀 | 올려 둔 소스만 앎 |
| 틀린 문제가 오답노트로, 다시 복습으로 이어짐 | 퀴즈를 내고 끝 |
| 코인·옹이로 계속할 이유를 만듦 | 계속하게 만드는 장치가 없음 |
| 학기·시간표·휴강 등 대학 생활 흐름에 맞춤 | 학사 개념이 없음 |

> NotebookLM은 자료를 이해하게 돕고, **MORAM은 그 이해를 시험 날까지 끌고 갑니다.**

## 🏗️ 아키텍처

```text
사용자 ──HTTPS──▶ 로드밸런서 (app.moram.tech)
                     │
        ┌────────────┴────────────┐
   서버 1 (KR-1)              서버 2 (KR-2)          ← Private Subnet · Auto Scaling
   Nginx(React) → FastAPI    Nginx(React) → FastAPI
        └────────────┬────────────┘
                     │ 내부 통신
        PostgreSQL · ChromaDB · NAS(강의자료)       ← Private Subnet (DB)
                     │
            NAT Gateway ──▶ Claude API · Gmail      ← 외부 호출
```

- 두 가용 영역(KR-1, KR-2)에 서버를 나눠 한쪽이 멈춰도 서비스가 유지됩니다.
- 마감 알림은 서버가 1분마다 확인하며, 서버가 두 대여도 DB 기록으로 중복 발송을 막습니다.
